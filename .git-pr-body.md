## Evidence
`teeny.self-improve` (`bin/act self-improve`, 09:40 UTC) failed on 2026-11-15, -16 and -17. Each run took about 6 s. All nine attempts (three days, each with cron's two immediate retries) in `state/act/self-improve/runs.jsonl` failed with the same error:

> `[oh] openhuman.inference_agent_chat: Prompt flagged for security review and was not processed. Please rephrase clearly.`

The spine log for 2026-11-17 09:40 gives the reason:

```
[prompt_injection] detection verdict source="local_ai.ops.agent_chat" verdict="review" reasons=input.oversized action="review_blocked" prompt_chars=86357
```

## Cause
The model provider was not at fault. No stream dropped in any of these runs.

The core screens every turn's message before the model sees it. Any message over `MAX_PROMPT_BYTES` (64 KiB, `vendor/openhuman/.../security/prompt_injection/detector.rs`) fails closed as `input.oversized`. That check is deterministic, so a retry, whether immediate or after a backoff, gets the same refusal in about 2 s.

self-improve has eight inputs. On the box today their sizes are: builds 27.0k, archive 23.0k, stimuli 17.9k, people 9.1k, issues 5.7k, frozen 4.2k, pending 1.5k, lessons 0. `bin/act` cut each input's text at 20,000 chars. That breaks the JSON, so builds and archive went to the model as escaped strings, which made them bigger still. The message came to 86,357 chars.

The other playbooks were not spared by luck. Their drafts in the last 72 h peak at about 64.5k chars, right at the edge.

## Fix
Inputs are now cut to fit, and they stay JSON. The new `bin/lib/act_fit.py` uses the Python 3.11 stdlib only.

- **Per input:** each input is held to `INPUT_SHARE = 20000` bytes of compact JSON, the same share as before. A list loses items from its end (hands answer newest first, and `--limit`/`--max` keep the front too), so the model still gets parseable JSON with whole items. A string is cut, with `...` added, only when no list is left to shorten. Text that is not JSON is cut like before.
- **All inputs together:** they get what the message has left under `TEENY_ACT_MAX_PROMPT_BYTES` (default 61,440). That leaves 4 KiB under the core's 65,536 for jq-vs-Python escaping differences. The room is shared out by one level: the largest cap that fits when applied to every input. Inputs under the level stay whole, and those over it are cut to it. A small input is never cut while a big one could be.
- `bin/act` measures the message frame (prompt plus answer instructions) before it fits the inputs. It never passes more than about 60 KB as one `--argjson`, which stays under Linux's 128 KiB per-argument limit.
- The model is told which inputs were cut. The run's line in `runs.jsonl` gets `cut: [...]`, and stderr logs it. An input that fits is passed byte-for-byte as before.

All of this happens before the draft turn, so nothing is sent twice and no send path changes.

Checked against the box's real self-improve inputs, captured with DRY_RUN=1 read verbs and run through this `bin/act` with a recording fake core. The message is 52,175 bytes. All eight inputs arrive as JSON objects, and builds, archive and recent are cut. The fit takes about 0.3 s.

## Not done: a draft retry
I was asked for a backoff retry of transient provider failures in the draft turn. The evidence shows it would not have saved any of these runs, so I left it out of this PR.

Across all playbooks since 2026-11-10, the "provider stream ended" draft failures come to 4 (reddit-browse 2, moltbook-helpdesk 1, build-idea 1). `provider_error.py` already classes them `passing`, exits 1, and cron retries them. If that's still wanted it can be a separate PR that reuses `guard/judge.py`'s `permanent()`/`RETRY_BACKOFFS` once #338 lands.

  - a cut input is JSON, with whole items from the front

  - the cut is named in the message and in the record

  - an input that fits has no cut note
