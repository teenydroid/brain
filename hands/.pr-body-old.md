## What went wrong

The builder's shell and file tools are rooted at `state/workbench/` (`brain/agents/builder.toml`, `scheduled_workspace = "state/workbench"`). The desk (`state/workbench/desk/build.json`) handed it two forms of the same folder, and neither was right for that root:

- `workdir`: `state/workbench/brain`, relative to the **checkout**. Its own prompt even said so ("workdir is the same folder, relative to the checkout").
- `workdir_path`: `/srv/teeny/state/workbench/brain`, container-absolute. The prompt and `builder-self.md` told it to use this one.
- `report_to` / `report_to_path`: the same problem, `state/workbench/desk/build-done.json` beside an absolute path.

Self job #7 (`dripsplan`) took `workdir` and wrote `state/workbench/brain/hands/dripsplan` from the workbench root. On the box that landed in `state/workbench/state/workbench/brain/hands/dripsplan` and `.../hands/lib/teeny_hands/dripsplan/__init__.py`. The real clone (`state/workbench/brain`) got nothing, so shipping it as it stood would have shipped no change. Daily build #6 also wrote `statediff.py` and `test_statediff.py` to the workbench root at first (00:16) before moving them into `daily-2026-11-15/` (00:30).

## What the builder sees now

Before (job 7):
```json
"workdir": "state/workbench/brain",
"workdir_path": "/srv/teeny/state/workbench/brain",
"report_to": "state/workbench/desk/build-done.json",
"report_to_path": "/srv/teeny/state/workbench/desk/build-done.json"
```
After:
```json
"workdir": "brain",
"report_to": "desk/build-done.json",
"paths": "Every path on this desk (workdir, report_to) is relative to state/workbench/, where your shell starts and your file tools resolve: use it exactly as written, never with state/workbench/ in front.",
"note": "you wrote under state/workbench/... by mistake last run (state/workbench/brain/hands/dripsplan, ...); your workdir is brain, write there. ..."
```
`note` only appears when the nested mirror holds files.

- Only what the builder is shown changes. A new `present` hook on `desk.run` rewrites the offer. The `build_jobs` row, `hands/build next`, `done` and `ship` still use the checkout-relative `workdir`. The task desk is untouched.
- A resumed job goes through the same `_offer` and then `_present`, so job #7's next run gets `workdir: "brain"` and the note.
- A report refused because the workdir is empty (or the clone has no change) now names the stray files and the right workdir in its reason. Nothing moves the files.
- An unknown report field now gets `unknown field(s) in the body: details; a report has only job_id, status, summary, tests, repo (put anything more in summary)`.
- The builder prompt (`builder.toml`), `builder-self.md`, `docs/hands.md` and `spine_live_test.sh` now use the relative form.

## Tests

Regression tests in `hands/tests/build/test_jobs.py` (`DeskTest`). All of them failed against the unfixed code:
- a daily job and a self job each show `workdir` relative to the workbench (`daily-<date>`, `brain`), with no `workdir_path` or `report_to_path`, and nothing shown starts with `state/workbench/` or the checkout path
- a resumed job shows the same workdir
- files in the nested mirror are named in the resumed job's `note` and in the rejection of an empty-workdir report, and are not moved
- an unknown report field is rejected with the allowed field list

`build.test_{jobs,selfclone,upstream,verify,ideas}`: 103 tests pass. The full suite result will follow in a comment.
