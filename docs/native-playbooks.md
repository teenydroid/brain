# Native playbooks

A playbook normally runs through `bin/act`: the inputs, one tool-less draft, the guard, the acting hand. A **native** playbook runs as an OpenClaw agent turn instead. The agent holds a shell, runs the inputs itself, writes the answer, and calls the acting hand, with CortexDB recall giving it memory. Judgment work moves this way; money, safety and fetchers stay deterministic command jobs. `gm` and `moltbook-general` are the first two.

## Converting a playbook

1. In its front matter add `run = "native"`. Optionally `max_per_run = N` (calls to the acting hand in one run, default 1, at most `max_per_day`).
2. Leave its job in `brain/cron.toml` as `command = "bin/act <name>"`. The schedule, `catch_up` rules and the no-catch-up rule for anything that speaks stay as they were. `bin/seed-cron` sees the playbook is native and seeds an agent job for the agent `pb-<name>` with the playbook's message instead. Do not add `make_up_hours`: a native run keeps no `bin/act` run log, and the policy refuses it.
3. `bin/seed-cron --check` and `python3 bin/lib/native_playbook.py spec brain <name> hands` tell you whether it can: the rules are in `bin/lib/playbook.py` (`_check_native`) and mirrored in `core/src/playbooks/load.ts`.
4. To go back to `bin/act`, delete the line. The job changes kind on the next seed.

Can run natively: output `post`, `reply`, `like`, `none`, `hand:x post|reply|like`, `hand:moltbook post|comment`; inputs that are hands; media `image` and `video`.
Cannot: `nudge`, `meme`, `datajob:` inputs, any other acting hand, and the playbooks `bin/act` holds to the studio switch (`x-quote`, `morning`, `take`, `show`, `shiplog`, `growth`, `brief`, `peer-quote`). A hand joins the native list (`NATIVE_HANDS` in both loaders) only after you have checked that its action path runs the guard, its caps and DRY_RUN inside itself, because `bin/act`'s own guard pass before a `hand:` output does not exist in a native turn.

## What the agent may run (the allowlist)

Generated by `core/src/agents/native.ts` and `core/src/agents/guardrails.ts`, enforced by `core/plugins/teeny-guardrails` (`exec.ts`, `native.ts`). The agent has `exec` and nothing else: no file tool, no browser, no helpers. Its shell runs exactly:

- each input, as declared (same argv), with `DRY_RUN=1` put in front by the plugin;
- the acting hand's verb(s), counted;
- media helpers when the playbook has `media`: `hands/image generate`, `hands/video generate`, `hands/x upload`;
- `printf`/`echo` into the hand, and the usual read-only commands under the usual path rules.

Anything else is refused: other hands, other verbs, `VAR=value` prefixes, files, `sh -c`.

## Caps, in code

In `before_tool_call`, per playbook, never only in the prompt:

- **per run**: calls to the acting hand (`max_per_run`, default 1);
- **per UTC day**: `max_per_day`, counted in `state/act/<name>/<date>`, the file `bin/act` uses, so switching a playbook between the two keeps the day's count. A refusal by the hand (exit 2) gives its count back; an error does not;
- **lock**: `state/locks/act-<name>`, the same lock `bin/act` takes: no two runs of one playbook at once, `bin/act` included. Released at `agent_end`, stale after 45 minutes;
- each run appends a line to `state/act/<name>/runs.jsonl` (`native: true`), where `bin/health` looks.

The hand still runs the guard, its own caps and `DRY_RUN` inside itself; the kill switches are read by the hand ("missing means off, the environment can only turn a switch off"). The plugin never sets or clears an environment variable except `DRY_RUN=1` on inputs and `TEENY_WRITER=<name>` on a `hand:` output (as `bin/act` did).

## Memory

The agent gets CortexDB recall before each turn like any agent. Add `pb-<name>` to the capture allowlist of `core/plugins/teeny-cortexdb` for any playbook that talks to people or makes content (`pb-gm` and `pb-moltbook-general` do) once that plugin is on main.

## What `bin/act` enforced, and where it lives now

| `bin/act` check | Native |
| --- | --- |
| day budget `max_per_day` (`state/act/<name>/<date>`) | teeny-guardrails `NativeState.reserve`, same file |
| actions in one run (answer array up to `left`) | `max_per_run`, same place |
| one run at a time (`state/locks/act-<name>`) | `NativeState.begin`, same lock |
| inputs only hands, `DRY_RUN=1` forced | allowlist matches exact argv; `DRY_RUN=1` put in front |
| money/secret hands never an input or output | `playbook.py` tables, plus `handsDeny` on every agent |
| required input empty -> skip before the model | **prompt only**: the message says so; the hand and cap still hold |
| input size cut to the 64 KiB screen | the message stays under 60 KiB (tested); the agent reads inputs itself |
| guard on text, then the hand takes the guard's text | the acting hand runs the guard itself (only such hands are native) |
| guard on an image description before `hands/image` | **prompt only**; the post's own text still goes through the guard |
| STUDIO switch skips replaced playbooks | those playbooks cannot be native |
| `TEENY_WRITER` for a `hand:` output | set by the plugin, not the agent |
| DRY_RUN, kill switches, caps inside the hand | unchanged, in the hand |
| drafting agent has no tools | the agent has a shell only, held to the allowlist |
| run log `state/act/<name>/runs.jsonl` | written at `agent_end` |
| provider-failure alarms and make-up | not kept: a native job makes nothing up |
| no catch-up for posting slots | unchanged: `cron_policy.py` and `cron.skipMissedJobs` |
